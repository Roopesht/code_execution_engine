**Phase:** 5 - Future Enhancements  
**Priority:** High

---

## Description

Enable users to execute code from a GitHub repository instead of manually entering code snippets. System reads files/folders from the repository and generates execution engine configuration.

---

## User Story

As a developer, I want to:
- Provide a GitHub repository link instead of typing code
- Have the system read files from the repository
- Execute tests against the repository code
- So that I can test code without copy-pasting

---

## Acceptance Criteria

- [x] API accepts GitHub repository URL in request
- [x] System clones or reads repository files (via GitHub API)
- [x] Supports public repositories
- [x] Auto-detects language (Python, JavaScript, React)
- [x] Reads source code and test files
- [x] Executes tests from the repository
- [x] Returns results same format as manual execution
- [x] Error handling for invalid/private repositories
- [x] No source code stored (ephemeral, like manual execution)

---

## Request Format

```json
{
  "language": "python",
  "exerciseId": "github-repo-test",
  "source": {
    "type": "github",
    "repository": "https://github.com/username/repo-name",
    "branch": "main",
    "paths": {
      "code": "src/solution.py",
      "tests": "tests/test_solution.py"
    }
  }
}
```

## Technical Considerations

1. **GitHub API vs Git Clone**
   - API: Lighter weight, no git installation needed, respects rate limits
   - Clone: Full repository, but slower and requires git
   - **Recommendation:** GitHub API for individual files

2. **Rate Limiting**
   - GitHub: 60 req/hour unauthenticated, 5000/hour authenticated
   - Solution: Use optional GitHub token from config

3. **Security**
   - Only read files, never write
   - Validate file paths (no ../../../etc/passwd traversal)
   - Delete cloned files immediately after execution

4. **Language Detection**
   - Python: `*.py` files in `src/` or root
   - JavaScript: `*.js` files or `package.json`
   - React: `*.jsx` files or `react` in `package.json`

---

## Testing Plan

1. Public Python repository (e.g., simple algorithm repo)
   - Verify files are fetched correctly
   - Verify tests execute and results return

2. Public JavaScript repository
   - Verify npm dependencies are installed
   - Verify tests execute correctly

3. Error scenarios
   - Invalid repository URL → 404
   - Private repository → 401
   - File not found → 400
   - Rate limit exceeded → 429
