# Story 5.3: Code Snippet Caching

[← Back to Scope Matrix](../01_scope-matrix.md)

---

**Phase:** 5 - Future Enhancements  
**Priority:** Medium  
**Status:** ⏳ Not Started

---

## Description

Save the last edited code snippet per user/session, allowing quick re-editing without re-entering the entire snippet.

---

## User Story

As a developer, I want to:
- Have my last code snippet automatically saved
- Retrieve it on the next request to edit and re-submit
- Avoid re-typing the entire code if I made small changes
- So that I can iterate quickly on code

---

## Acceptance Criteria

- [x] Last code snippet is saved after execution
- [x] Saved per user (via API key or session)
- [x] Saved per exercise (different exercises = different cache)
- [x] Cache returns latest snippet on request
- [x] Cache can be cleared on demand
- [x] Cache has configurable TTL (default: 7 days)
- [x] Cache size limit enforced (e.g., 100MB per user)
- [x] Privacy: Only user can access their own cache
- [x] Optional feature (client-side opt-in)

---

## Request Format

### Save snippet (automatic after execution)
```json
{
  "language": "python",
  "exerciseId": "algo-sort",
  "code": "def bubble_sort(arr):\n    return sorted(arr)",
  "tests": "def test_sort(): assert bubble_sort([3,1,2]) == [1,2,3]",
  "cacheKey": "algo-sort-v1"  // optional, defaults to exerciseId
}
```

### Retrieve cached snippet
```json
{
  "action": "retrieve_cache",
  "cacheKey": "algo-sort-v1"
}
```

## Cache Storage

### Database Schema (Optional SQL storage)
```sql
CREATE TABLE code_cache (
  id UUID PRIMARY KEY,
  user_id VARCHAR(255),        -- From API key
  exercise_id VARCHAR(255),
  cache_key VARCHAR(255),
  language VARCHAR(50),
  code TEXT,
  tests TEXT,
  last_saved TIMESTAMP,
  created_at TIMESTAMP,
  ttl_days INT DEFAULT 7
);

CREATE INDEX idx_user_exercise ON code_cache(user_id, exercise_id);
```

### Alternative: In-Memory Cache
- Use Redis or similar
- TTL: 7 days per entry
- Max size: 100MB per user

## API Endpoints

### GET /cache/{cacheKey}
Retrieve cached snippet
```bash
GET /cache/algo-sort-v1
X-API-Key: <key>

Response:
{
  "cacheKey": "algo-sort-v1",
  "language": "python",
  "exerciseId": "algo-sort",
  "code": "def bubble_sort(arr):\n    return sorted(arr)",
  "tests": "def test_sort(): assert bubble_sort([3,1,2]) == [1,2,3]",
  "savedAt": "2024-07-09T10:30:00Z",
  "expiresAt": "2024-07-16T10:30:00Z"
}
```

### DELETE /cache/{cacheKey}
Clear specific cache entry
```bash
DELETE /cache/algo-sort-v1
X-API-Key: <key>

Response:
{
  "status": "deleted",
  "cacheKey": "algo-sort-v1"
}
```

### DELETE /cache
Clear all user's cache
```bash
DELETE /cache
X-API-Key: <key>

Response:
{
  "status": "cleared",
  "count": 5  // Number of entries deleted
}
```

## Client Usage Example

```python
# 1. User submits code for first time
response = requests.post(
    "http://localhost:7998/execute",
    json={
        "language": "python",
        "exerciseId": "algo-sort",
        "code": "def bubble_sort(arr):\n    return sorted(arr)",
        "tests": "def test_sort(): assert bubble_sort([3,1,2]) == [1,2,3]"
    },
    headers={"X-API-Key": "key"}
)
# Response includes cache info

# 2. User wants to edit and re-run
# First, retrieve cached snippet
cached = requests.get(
    "http://localhost:7998/cache/algo-sort-v1",
    headers={"X-API-Key": "key"}
).json()

# 3. User edits code locally
edited_code = cached["code"].replace("sorted", "custom_sort")

# 4. Submit edited code (auto-saves again)
response = requests.post(
    "http://localhost:7998/execute",
    json={
        "language": cached["language"],
        "exerciseId": cached["exerciseId"],
        "code": edited_code,
        "tests": cached["tests"]
    },
    headers={"X-API-Key": "key"}
)
```

## Security Considerations

1. **User Isolation**
   - Extract user_id from API key
   - Only return own cache entries
   - Reject access to other users' cache

2. **Cache Invalidation**
   - TTL-based cleanup (default 7 days)
   - Manual deletion supported
   - Automatic cleanup on user request

3. **Data Privacy**
   - Cache stored encrypted at rest (if using database)
   - Cache not visible in logs
   - Cache cleared on logout/session end

---

## Testing Plan

1. **Save and retrieve**
   - Execute code
   - Retrieve cache
   - Verify code matches

2. **TTL and expiration**
   - Create cache
   - Verify expires at correct time
   - Attempt retrieve after expiration → 410

3. **User isolation**
   - Create cache with user1 API key
   - Attempt retrieve with user2 API key → 403

4. **Size limits**
   - Create 20 large snippets (5MB each)
   - Verify 21st fails with 413

5. **Edge cases**
   - Cache key not found → 404
   - Delete non-existent cache → 204
   - Clear empty cache → 200
