# Story 5.2: Multiple Files Support

[← Back to Scope Matrix](../01_scope-matrix.md)

---

**Phase:** 5 - Future Enhancements  
**Priority:** High  
**Status:** ⏳ Not Started

---

## Description

Enable users to submit multiple code files (instead of single snippet) to be executed together. Useful for projects with multiple modules/classes that need to work together.

---

## User Story

As a developer, I want to:
- Submit multiple Python/JavaScript files at once
- Have the system organize them in the workspace
- Execute tests that import from all provided files
- So that I can test complex projects with multiple modules

---

## Acceptance Criteria

- [x] API accepts array of files in request
- [x] Each file has name and content
- [x] Files are written to workspace with correct paths
- [x] Tests can import from any provided file
- [x] Backward compatible with single-file requests
- [x] File path validation (no directory traversal)
- [x] Support nested directories (e.g., `models/user.py`)
- [x] Error handling for duplicate filenames
- [x] No persistent storage of files (ephemeral)

---

## Request Format

```json
{
  "language": "python",
  "exerciseId": "multi-file-test",
  "files": [
    {
      "name": "solution.py",
      "content": "def calculate(x):\n    return x * 2"
    },
    {
      "name": "helpers.py",
      "content": "def validate(x):\n    return x > 0"
    },
    {
      "name": "models/user.py",
      "content": "class User:\n    def __init__(self, name):\n        self.name = name"
    }
  ],
  "tests": "import solution\nimport helpers\nfrom models.user import User\n\ndef test_calculate():\n    assert solution.calculate(5) == 10"
}
```

---

## Implementation Tasks

- [ ] Update ExecutionRequest model to support `files` array
- [ ] Implement file path validation (no `../` traversal)
- [ ] Create nested directories as needed
- [ ] Handle duplicate filenames
- [ ] Support both `code` (backward compat) and `files` (new)
- [ ] Update workspace preparation logic
- [ ] Ensure test imports work correctly
- [ ] Add file size validation (e.g., max 10MB total)
- [ ] Security: Validate all file paths
- [ ] Update API documentation

---

## Workspace Structure Example

```
/tmp/executor_<uuid>/
├── solution.py          (file 1)
├── helpers.py           (file 2)
├── models/              (nested dir)
│   └── user.py          (file 3)
└── test_solution.py     (tests)
```

---

## Backward Compatibility

The `code` field in ExecutionRequest still works:

```json
{
  "language": "python",
  "code": "def calculate(x):\n    return x * 2",
  "tests": "def test_calculate(): assert calculate(5) == 10"
}
```

**Implementation:** Convert single `code` to `files: [{name: "solution.py", content: code}]`

---

## Error Scenarios

1. **Duplicate Filenames**
   - Error: `"Duplicate file: solution.py"`

2. **Invalid Paths**
   - Reject: `"../../../etc/passwd"`
   - Reject: `/etc/passwd` (absolute paths)
   - Allow: `models/user.py` (relative paths)

3. **File Size**
   - Reject if total > 10MB
   - Error: `"Total file size 15MB exceeds limit of 10MB"`

4. **Empty Files Array**
   - Error: `"At least one file required"`

---

## Testing Plan

1. **Python with 3 files**
   - Submit solution.py, helpers.py, models/user.py
   - Verify all are written to workspace
   - Verify tests can import from all files

2. **JavaScript with nested structure**
   - Submit index.js, lib/utils.js, lib/validate.js
   - Verify directory structure created
   - Verify imports work correctly

3. **Error scenarios**
   - Duplicate filenames → 400 error
   - Path traversal attempts → 400 error
   - File size limit → 413 error

4. **Backward compatibility**
   - Old requests with `code` field still work
   - Converted internally to files format
